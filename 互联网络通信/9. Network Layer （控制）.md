# 网络层的控制平面
|概念|功能|
|---|---|
|**数据平面**|负责实际转发数据包（如 IP 数据报）——“做事情”|
|**控制平面**|负责决定如何转发数据包——“决策”|
## 控制平面的功能：
1. **Set up routes within a single network**
	- 协议负责：
	    - 发现邻居路由器
	    - 交换拓扑信息
	    - 计算最佳路径
	    - 更新路由表
2. **Distributing and updating routes**
	- 使用 **洪泛（Flooding）** 或 **增量更新**
	- 带有 TTL 的消息防止无限循环
3. **Convergence time**
	- 尽量缩短收敛时间（毫秒级理想）
4. **Avoiding loops**
	- 使用 **跳数限制**（如 RIP 最多 15 跳）
	- 使用 **序列号** 或 **老化机制**
	- 在 BGP 中使用 **AS_PATH** 避免重复 AS

| 协议                                     | 类型                    | 用途                       |
| -------------------------------------- | --------------------- | ------------------------ |
| **RIP (Routing Information Protocol)** | 距离矢量（Distance Vector） | 小型网络，简单易用，但最大跳数为 15      |
| **OSPF (Open Shortest Path First)**    | 链路状态（Link State）      | 大型企业/ISP 内部，支持 VLSM、快速收敛 |
| **BGP (Border Gateway Protocol)**      | 路径矢量（Path Vector）     | AS 之间通信，互联网骨干网标准         |


# Internet Routing
## 层次结构
1. Autonomous Systems (AS)
2. Routers within each AS

### Autonomous Systems（AS）
> **AS = 自治系统**
- 是一个**独立管理的网络区域**
- 通常对应一家公司、运营商或组织
- 具有自己的 IP 地址池、路由策略和管理员
### Intra-domain Routing（域内路由）
> 使用 **IGP（Interior Gateway Protocol）** 协议：
- 包含
	- **距离矢量（Distance Vector）**：
	    - 如 **RIP**：基于跳数选择最短路径
	    - 优点：简单
	    - 缺点：收敛慢，不适合大型网络
	- **链路状态（Link State）**：
	    - 如 **OSPF**：每个路由器了解全网拓扑，计算最短路径
	    - 优点：收敛快、支持复杂策略
	    - 缺点：配置复杂，资源消耗大

### AS 之间：Inter-domain Routing（域间路由）
> 使用 **EGP（Exterior Gateway Protocol）** 协议：
- **BGP（Border Gateway Protocol）**
- 当前互联网的标准：**BGP-4**（RFC 4271）
特点：
- 不仅寻找“最短路径”，还考虑**策略、成本、安全性、带宽**
- 支持 **多路径选择**
- 允许运营商根据商业关系选择路由（如优先走自家线路）

## AS的重要性
1. **Routing algorithms are not efficient enough to execute on the entire Internet topology**
	- 整个互联网有超过 **100万个路由器** 和 **数百万条链路**
	- 全局路由算法（如 Dijkstra）计算量太大，无法实时运行
	- 分而治之：把互联网分成小块（AS），每块自己管理
2. **Different organizations may use different routing policies**
	- 每个组织有自己的网络目标：
	    - 成本最小化
	    - 性能最大化
	    - 安全优先
	    - 政策合规（如不经过某国）
3. **Allows organizations to hide their internal network structure**
	- AS 可以对外隐藏其内部拓扑细节
	- 只暴露必要的路由信息（如 “我有 192.168.1.0/24”）
	- 提高安全性和隐私性
4. **Allows organizations to choose how to route across each other (BGP)**
	- BGP 是一种“**策略驱动**”的协议
	- 不只是找最短路径，而是根据商业合同、成本、延迟等选择路径
	- 支持 **多归属（Multi-homed）**、**负载均衡**、**故障切换**

| 概念            | 说明                    |
| ------------- | --------------------- |
| **AS（自治系统）**  | 一个独立管理的网络区域，拥有自己的路由策略 |
| **IGP（域内路由）** | 如 RIP、OSPF，用于 AS 内部路由 |
| **EGP（域间路由）** | 如 BGP，用于 AS 之间的通信     |
| **BGP**       | 互联网的“大脑”，决定全球数据流走向    |
| **控制平面**      | 决定“怎么走”，而非“走哪里”       |

**互联网不是一张大网，而是一张由无数自治系统（AS）组成的“拼图”。每个 AS 是一个独立王国，内部用 OSPF/RIP 管理交通，彼此之间用 BGP 协商路线——这就是现代互联网能够稳定、灵活、可扩展的根源。**


# 路由算法
## Routing on a Graph
**从源节点到目的节点，寻找一条“好”的路径**
### 什么是“好”的路径？

|标准|解释|
|---|---|
|**最短路径**|最常见标准，通常指跳数最少或总代价最小|
|**负载均衡**|分散流量，避免某条链路过载|
|**最低成本**|经济角度，如运营商间结算费用|
- 对用户：延迟低
- 对运营商：带宽便宜、稳定
- 对网络：公平、不拥塞

### 网络建模为图（Graph）
将网络抽象成一个**有向加权图**：

|实体|图论对应|
|---|---|
|路由器|**节点（Node / Vertex）**|
|链路（Link）|**边（Edge）**|
|链路权重（Cost）|**边的权值（Weight）**|
边的权重可以表示： 
- 延迟（delay）
- 拥塞程度（congestion level）
- 带宽（bandwidth）
- 成本（cost）
- 跳数（hop count）

例如：
- A → D → E → F：代价 = 1 + 1 + 2 = **4**
- A → B → C → F：代价 = 2 + 3 + 5 = **10**
所以第一条更优！

## Shortest Path Routing
| 算法                         | 类型                    | 应用场景      |
| -------------------------- | --------------------- | --------- |
| **Bellman-Ford Algorithm** | 距离矢量（Distance Vector） | RIP 协议基础  |
| **Dijkstra’s Algorithm**   | 链路状态（Link State）      | OSPF 协议基础 |
### “最短路径”意味着什么？
| 选项                             | 含义      | 是否合理？           |
| ------------------------------ | ------- | --------------- |
| a. Minimize mean packet delay  | 减少平均包延迟 | ✔️ 常见目标         |
| b. Maximize network throughput | 提高吞吐量   | ✔️ 在高负载时重要      |
| c. Minimize number of hops     | 减少跳数    | ✔️ 简单有效，RIP 的标准 |
**代价最小**

### Dijkstra’s Shortest Path Algorithm
从源点出发，计算到所有其他节点的最短路径（单源最短路径）
1. **初始化**：
    - 设置源节点距离为 0
    - 其他所有节点距离设为 ∞（无穷大）
    - 所有节点标记为“临时”
2. **循环直到到达终点**：
    - 选择当前距离最小的“临时”节点作为“工作节点”（working node）
    - 将其标记为“永久”（已确定最短路径）
    - 更新其邻居节点的距离：
        - 如果 `dist[当前节点] + 边权 < dist[邻居]`，则更新邻居的距离和前驱节点
3. **重建路径**：
    - 从终点回溯，通过前驱节点记录路径

- 使用数组：$Θ(V²)$ —— 适合小规模网络
- 使用最小堆：$Θ((V + E) log V)$ —— 更高效，现代实现常用

### 贝尔曼-福特算法
 **迭代松弛**：
- 每一轮尝试通过已有路径改进所有节点的距离
- 最多需要 **V-1** 轮，因为最长简单路径最多有 V-1 条边
- **可以检测负权环**（Negative Cycle）
- 如果第 V 轮还能更新距离 → 说明存在负环（无限优化）
总体复杂度：$Θ(V × E)$

### 选择算法的依据
- **Dijkstra**：每个路由器都知道**整个网络的拓扑结构**（链路状态）
    - 如 OSPF：广播 LSA（链路状态通告）
    - 每台路由器运行 Dijkstra 计算全局最短路径
- **Bellman-Ford**：只知**邻居信息**（距离矢量）
    - 如 RIP：定期向邻居发送“我到 X 的距离是 Y”
    - 逐步收敛，无需全局知识

| 类比  | Dijkstra     | Bellman-Ford |
| --- | ------------ | ------------ |
| 角色  | 地图导航员（有完整地图） | 行走探索者（只看眼前）  |
| 方法  | 一次性算出最优路径    | 一步步逼近最优      |
| 效率  | 高            | 低            |
| 安全性 | 无负环风险        | 可检测负环        |

### Adaptive Routing（自适应路由）
- 路由决策会根据网络状态动态调整
- 与“静态路由”相对（如手动配置固定路径）
自适应路由分为两类：
#### 集中式（Centralized）
- 存在一个**中央控制器**（如 RCC，Routing Control Center），负责全局计算和分发路由。
- 所有路由器将拓扑信息上报给中心，由中心统一计算最短路径，并下发给各节点。

#### 分布式（Distributed）
- 没有中央控制，每个路由器**独立运行**，通过交换信息协作完成路由决策。
- ✅ **现代互联网的核心模式**（如 OSPF、BGP）
### Intradomain vs Interdomain Routing
| 类型                      | 英文缩写 | 中文名称 | 应用场景         |
| ----------------------- | ---- | ---- | ------------ |
| **Intradomain Routing** | IGP  | 域内路由 | 同一自治系统（AS）内部 |
| **Interdomain Routing** | EGP  | 域间路由 | 不同 AS 之间通信   |
- **IGP（Interior Gateway Protocol）**：
    - RIP、OSPF、IS-IS、PNNI
- **EGP（Exterior Gateway Protocol）**：
    - BGP（Border Gateway Protocol）、IDRP（已废弃）

### Routing problem
在一个拥有 N 个节点的网络中，每个节点只知道：
- 它的**直接邻居**是谁
- 到**每个邻居的链路代价**（cost）
- 它如何知道去任意其他节点的最短路径？

- 局部信息 → 全局知识
	- 通过**消息交换**来传播拓扑信息
	- 使用特定算法（如 Bellman-Ford 或 Dijkstra）计算最短路径

| 方法                        | 描述                              |
| ------------------------- | ------------------------------- |
| **Distance Vector（距离矢量）** | 每个路由器定期向**邻居**发送“我**到所有目标的距离**” |
| **Link State（链路状态）**      | 每个路由器广播“**我的邻居和链路状态**”，全网共享拓扑   |
让每个路由器都能构建出完整的**路由表**，从而决定数据包转发方向。

## 域内路由协议详解
### Distance Vector Routing（距离矢量路由）
基于 **Bellman-Ford 算法**
协议代表：**RIP（Routing Information Protocol）**
**工作方式：**
- 每个路由器周期性地（通常每30秒）向邻居发送自己的“距离矢量”
- 使用跳数（hop count）作为度量标准（最大跳数为15）
- 包含内容：“我到 X 的距离是 Y”
- 接收方根据收到的信息更新自己的路由表`如果 dist[邻居] + cost < 我当前到目标的距离，则更新`
#### Distance Vector
是一种分布式路由算法，**每个节点**维护一个到所有**目的地的最短路径**成本表，并与邻居交换该信息以逐步学习全局最优路径。
- 它是一个表格，记录了从当前节点到每一个可能目的地的**当前已知最低代价（cost）**
- 每个条目包含：
    - 目的地（Destination）
    - 到达该地的最小代价（Cost）

| Destination | Cost |
| ----------- | ---- |
| A           | 7    |
| B           | 1    |
| D           | 2    |
| E           | 5    |
| F           | 1    |
#### Exchange vectors among neighbors
- 所有路由器定期向其直接邻居发送自己的“距离矢量”
- 接收方根据收到的信息更新自己的路由表
- 目标：通过反复交换信息，最终让每个节点知道整个网络中最短路径
- 初始时，节点只知道：
    - 自己的直连邻居
    - 到这些邻居的链路代价
- 其他节点的代价设为 ∞（无穷大），表示不可达

#### 算法执行步骤
![[Pasted image 20260101195529.png]]
1. **Wait for event**
- 等待两种触发条件之一：
    - 本地链路代价发生变化（如链路故障或恢复）
    - 收到来自邻居的更新消息（距离矢量）
2. **Recompute distance table**
- 使用 Bellman-Ford 更新规则重新计算到各目的地的最小代价：
```
    1D(A,Y) = min( D(A,Y), D(A,V) + D(V,Y) )
```
- `D(A,Y)`：A 到 Y 的当前最小代价
- `D(A,V)`：A 到邻居 V 的代价
- `D(V,Y)`：V 告诉 A 的“它到 Y 的代价”
3. **Notify neighbors if changed**
	- 如果发现任何目的地的最短路径发生了变化，则将新的距离矢量发送给所有邻居
4. 表格收敛
	- 此时所有路径均已收敛，且是最短路径。
#### 计数到无穷（Count-to-Infinity）
当链路失效时，DV 算法可能出现的严重问题：**计数到无穷（Count-to-Infinity）**
##### 场景设定：
- 三节点网络：A-B-C
- 边权：
    - A-B: 1
    - B-C: 1
    - A-C: 50（高代价）
初始时：
- A→C：可选 A→C (50) 或 A→B→C (1+1=2)
- 所以 A 选择 A→B→C，成本为 2
##### 当 A-C 链路断开（或变坏）？
假设 A-C 断开，A 将无法直接访问 C。
但 B 和 C 仍能通信。
正常情况：A 应该继续使用 A→B→C（成本 2）
但问题来了：如果 **B 没有及时通知 A**，而 A 又错误地认为自己可以直接到 C（比如误判），就会发生“计数到无穷”。
#####  解决方案
1. **水平分割（Split Horizon）**：不要把从邻居学到的路由再告诉它
2. **毒性逆转（Poison Reverse）**：明确告诉邻居“这条路不可达”
3. **触发更新（Triggered Updates）**：一旦变化立刻发送，避免周期等待
4. **路由毒化（Route Poisoning）**：设置成本为 ∞ 表示失效
5. **保持计时器（Hold-down Timer）**：防止快速波动

#### 毒性逆转（Poison Reverse）
是**距离矢量路由协议**（如 RIP）中用于**防止路由环路和加速收敛**的一种重要机制，尤其用于缓解著名的 **“计数到无穷”**（Count-to-Infinity）问题。

核心概念：
- **不要把从某个邻居学到的路由，再以正常形式告诉它；如果必须告诉，就把它标记为‘不可达’。**
- **如果路由器 X 通过邻居 Y 到达目的地 Z，那么 X 在向 Y 发送路由更新时，应将 Z 的代价设为 ∞**（即“毒化”该路由）
链路失效后的处理：
- B 断开与 C 的连接
- B 想查是否有替代路径 → 查看邻居 A 的通告
- 但 A **对 B 宣告的是：A 到 C = ∞**
- 所以 B 知道：“A 也无法到达 C”
- B 立即将 C 标记为不可达（代价 = ∞）
- **没有错误路径产生，快速收敛！**
### Link State Routing（链路状态路由）
基于 **Dijkstra 算法**
要求每个节点都掌握整个网络的拓扑结构，从而独立计算最短路径。
协议代表：**OSPF（Open Shortest Path First）**
工作方式：
- 每个路由器将自身的“链路状态”广播给全网（称为 **flooding**）
- 包含内容：“我是 A，我连着 B 和 D，代价分别是 2 和 1”
- 所有路由器最终获得相同的网络拓扑图
- 每个路由器独立运行 Dijkstra 算法，计算出到所有目的地的最短路径

#### 算法特征
1. **Each node knows its connectivity and cost to direct neighbors**
	- 每个节点（路由器）知道：
	    - 它直接连接了哪些邻居
	    - 到每个邻居的链路代价（如延迟、带宽、跳数等）
2. **Each node tells every other node this information**
	- 节点将本地的“链路状态”信息广播给全网所有其他节点
	- 这些信息称为 **链路状态包**（Link State Packet, LSP）
3. **Each node learns complete network topology**
	- 所有节点通过收集来自各处的 LSP，构建出一个完整的网络拓扑图
	- 每个节点都有相同的“地图”——即全局视图
4. Use Dijkstra to compute shortest paths
	- 每个节点使用 Dijkstra 算法 在自己的完整拓扑图上运行
	- 计算从自身到所有目的地的最短路径树（Shortest Path Tree）
	- 得到最优路由表

#### 洪泛机制（Flooding）
确保所有节点都能收到最新的链路状态更新。
##### Link State Packet
- 每个节点定期生成一个 LSP（也叫 LSA，Link State Advertisement）
- 内容包括：
    - **发送者 ID**：哪个节点发的
    - **邻居列表 + 成本**：例如，“我连着 B（成本2）、C（成本1）”
    - **序列号**（64-bit）：用于区分新旧版本（防止过期消息重复传播）
    - **TTL（Time to Live）**：限制洪泛范围，避免无限循环
##### Flood is reliable (ack + retransmission)
- 洪泛不是“发完就不管”，而是**可靠的**
- 使用 ACK + 重传机制确保每条 LSP 都被正确接收
- 若未收到 ACK，则重新发送
##### Receivers flood LSPs to their own neighbors
- 接收 LSP 的节点会将其转发给自己的所有邻居
- **例外**：如果该节点是原始发送者，就不转发（避免环路）
##### LSPs also generated when link states change
- 不仅周期性发送，当链路状态改变时（如断开或恢复），立即触发 LSP 发送
- 实现快速收敛

### 链路状态协议
OSPF 和 IS-IS 是当前互联网中最常用的两种链路状态路由协议，虽然功能相似，但设计理念和应用场景有所不同。

|特性|**OSPF**|**IS-IS**|
|---|---|---|
|**适用对象**|公司、数据中心|ISP（互联网服务提供商）|
|**协议设计**|基于 IP 设计|早期为 OSI 设计，后兼容 IP|
|**灵活性**|更多可选特性（如 QoS、MPLS 支持）|更简洁，更少“花哨”功能|
|**网络开销**|相对“健谈”（chatty）|更安静，减少控制流量|
|**IP 支持**|基于 IPv4，OSPFv3 才支持 IPv6|同时支持 IPv4 和 IPv6，无需额外版本|

#### Different Organizational Structure
##### OSPF：基于区域（Area）的重叠结构
- 网络划分为多个 **Area（区域）**
- **Area 0 是核心骨干区（Backbone Area）**
- 所有非零区域必须通过 Area 0 互联
- 区域之间可以**重叠**（即一个路由器属于多个区域）
- 区域边界路由器（ABR）负责跨区域路由
![[Pasted image 20260101201053.png]]


##### IS-IS：两级层次结构（Two-Level Hierarchy）
- 分为两个层级：
    - **Level 1（L1）**：区域内路由（Intra-area）
    - **Level 2（L2）**：骨干路由（Inter-area / Backbone）
- **Level 2 是真正的骨干网络**
- Level 1 路由器只能看到本区域内的拓扑
- Level 2 路由器连接所有区域，负责跨区域通信
- 没有“重叠”的概念，结构更清晰

# BGP
![[Pasted image 20260102150051.png]]
## 内部路由器（Interior Routers）：
- 蓝色路由器位于每个 AS 内部
- 使用 **内部网关协议**（IGP），如 OSPF、IS-IS 等
- 负责在 AS 内部进行高效路由（intra-domain routing）

## BGP 路由器（Border Gateway Protocol Routers）：
- 棕色路由器位于 AS 边界
- 运行 **BGP** 协议，负责与其他 AS 交换路由信息
- 是“连接世界”的桥梁


## 自治系统编号（ASN）
每个 AS 都有一个唯一的标识符——**AS Number (ASN)**，用于在全球范围内识别该网络。
### ASN 的格式：
- 原始为 **16-bit**，范围是 `1 – 65535`
- 最新协议支持 **32-bit ASN**（扩展到约 40 亿个）
- `64512 – 65535` 是保留值，通常用于私有或测试环境

| 组织       | ASN                     |
| -------- | ----------------------- |
| AT&T     | 5074, 6341, 7018        |
| Sprint   | 1239, 1240, 6211        |
| ELTE     | 2012                    |
| Google   | 15169, 36561（原 YouTube） |
| Facebook | 32934                   |


## 域间路由（Inter-Domain Routing）
域间路由解决的是 **不同 AS 之间如何通信** 的问题，涉及整个互联网的互联互通。
- 所有 AS 必须使用**相同的协议**来交换路由信息
- 否则无法实现全球互通

|类型|特点|
|---|---|
|**Intra-domain**（内域）|使用 IGP（如 OSPF），追求最短路径、高性能|
|**Inter-domain**（外域）|使用 BGP，关注政策、经济成本、稳定性|
### 域间路由的需求：
1. **可扩展性（Scalability）**
    - 支持数万个 AS 的动态变化
2. **灵活选路能力**
    - 可基于多种因素选择路径：
        - 成本（Cost）
        - 故障绕行（Routing around failures）
        - 政策优先级
**BGP 是一种 Path Vector（路径向量）协议**，不仅告诉“下一跳”，还传递“完整路径”（AS 路径列表），防止环路并支持策略控制

## 边界网关协议（Border Gateway Protocol）
**BGP** 是互联网中唯一被广泛采用的 **域间路由协议**，被誉为“互联网的神经系统”。
- 是互联网事实上的 **inter-domain protocol**
- 属于 **policy-based routing protocol**（基于策略的路由协议）

### 技术本质：
- 使用 **Bellman-Ford 算法 + Path Vector 机制**
- 每条路由包含：
    - 目标网络
    - 下一跳
    - **AS 路径（AS PATH）**：记录经过的所有 AS 编号
        - 用于检测环路（若发现自己的 ASN 出现在路径中 → 环路）
        - 支持策略过滤
- 决策驱动因素：
	- **经济性**（Economics）而非性能

### BGP Relationships
**BGP 对等体关系（Peering Relationships）**
BGP 路由器之间的连接关系决定了数据流的方向和策略。
#### 三种主要关系类型：
#### 1. Customer → Provider
- 客户（Customer）付费给运营商（Provider）获取互联网接入
- Provider 会为客户发布其网络前缀
- 但客户不能自由转发其他客户的流量（除非特殊许可）
数据流向：客户 → 提供商（上行），提供商 → 客户（下行）
#### 2. Provider → Customer
- 同上，只是方向相反
- 提供商对外提供服务
#### 3. Peer to Peer（对等互联）
- 两个 AS 之间互相交换流量，**不收取费用**
- 通常发生在大型 ISP 之间或同等地位的企业之间
- 双方共享资源，互惠互利
#### 层次关系
![[Pasted image 20260102151042.png]]
- 上层“Provider”与下层“Customer”是客户-供应商关系
- “Customer Peer 1”和“Customer Peer 3”之间有对等连接（水平线）
- 中间的“Provider”既是上游也是下游

##### 一级网络（Tier 1 Network）
Tier 1 网络是互联网的“骨干力量”，它们彼此直接互联，无需通过第三方付款即可访问全球。
特征：
- **完全对等互联**（Full Mesh）
- 不依赖任何其他网络获取互联网访问
- 自己拥有全球覆盖能力
- 通常由大型电信运营商组成
不同的一级网络它们之间形成了一个**全连接的网状结构**（Full Mesh），任意两个节点都直接相连

| 概念                 | 解释                                         |
| ------------------ | ------------------------------------------ |
| **AS（自治系统）**       | 由单一实体管理的网络集合，拥有独立路由策略                      |
| **ASN（AS Number）** | 唯一标识一个 AS 的数字，当前已超 4 万个                    |
| **BGP**            | Internet 的 de facto 域间路由协议，基于策略和路径向量       |
| **Path Vector**    | 记录完整 AS 路径，防止环路，支持策略控制                     |
| **BGP 关系**         | 分为 Customer-Provider 和 Peer-to-Peer，决定流量走向 |
| **Tier 1 网络**      | 彼此全互联的顶级 ISP，构成互联网骨干                       |
| **AS 拓扑**          | 具有高度集中性和层级结构，少数核心主导全局                      |

#### 对等（Peer）的好处：

| 理由                                                          | 解释                                                   |
| ----------------------------------------------------------- | ---------------------------------------------------- |
| **Reduce upstream costs**                                   | 通过直接互联减少支付给上游 ISP 的费用。例如：A 和 B 直接连接后，不再需要经过昂贵的第三方中转。 |
| **Improve end-to-end performance**                          | 减少跳数和延迟，提升用户体验。数据包不需要绕远路，端到端性能更好。                    |
| **May be the only way to connect to parts of the Internet** | 某些网络只能通过对等才能访问。比如跨国通信或特定区域的互联网接入。                    |

#### 不对等（Don’t Peer）的原因：

| 理由                                                    | 解释                                       |
| ----------------------------------------------------- | ---------------------------------------- |
| **You would rather have customers**                   | 更愿意让对方成为你的客户并付费，而不是平等对等。这是商业模式的选择。       |
| **Peers are often competitors**                       | 很多对等方是竞争对手，比如 AT&T vs Verizon。他们不愿意共享资源。 |
| **Peering agreements require periodic renegotiation** | 协议需要定期重新谈判，增加了管理成本和不确定性。                 |

#### Two Types of BGP Neighbors
![[Pasted image 20260102151831.png]]
####  eBGP（External BGP）：
- 在 **不同 AS 之间** 的 BGP 会话
- 用于交换外部路由信息
- 示例：AS-1 与 AS-2 之间的连接
#### iBGP（Internal BGP）：
- 在 **同一 AS 内部** 的 BGP 会话
- 用于将从 eBGP 学到的路由传播到 AS 内部其他路由器
- 注意：iBGP 不像 IGP 那样自动扩散，必须手动配置全连接（Full Mesh）
##### Full iBGP Meshes
![[Pasted image 20260102152101.png]]
- 橙色线表示 **iBGP 全网状连接**（每个路由器都与其他所有 iBGP 路由器建立会话）
- 红色箭头表示 **eBGP 连接**（对外）
**原因：**
- IGP（如 OSPF）只关心最短路径，不携带策略信息。而 BGP 路由包含复杂的策略（如优先级、AS-path 等），必须用 iBGP 传递。
- iBGP 有严格的规则防止环路（如不允许将从某个 iBGP 邻居学到的路由再发回给它）。
- iBGP 更新不会触发下游广播，避免不必要的泛洪。
#### IGP（Interior Gateway Protocol）：
- 如 OSPF、IS-IS，用于 AS 内部快速路由
- 外部路由器也运行 IGP，确保内部可达性

#### 总结
- **eBGP = 外部邻居，跨 AS**
- **iBGP = 内部邻居，同 AS**
- **IGP = 内部路由协议，负责本地连通**

### BGP协议
#### Path Vector Protocol（路径向量协议）
![[Pasted image 20260102152321.png]]
- 五个 AS 组成网络拓扑
- 每个 AS 包含一个 IP 前缀（如 `120.10.0.0/16`）
- 红色框显示 AS 之间的路径信息
核心概念：AS-path
> **AS-path：一条路由所经过的 AS 序列**

| 功能                       | 说明                                                    |
| ------------------------ | ----------------------------------------------------- |
| **Loop detection**       | 如果某条路径中出现了自己的 AS 号，则判定为环路。例如：AS 1 → AS 2 → AS 1 是非法的。 |
| **Policy enforcement**   | AS 可以根据 AS-path 制定策略，如“不接受来自特定 AS 的路由”。               |
| **Path selection**       | 选择最短路径（AS 数最少）、最低代价等。                                 |
| **Longest prefix match** | 路由决策基于最长前缀匹配原则（标准 IP 路由行为）。                           |
**路径向量协议 = 距离矢量 + 完整路径记录**

#### Path-Vector Routing（路径向量路由）
![[Pasted image 20260102153007.png]]
- 红色箭头表示 **路由更新消息**
- 蓝色箭头表示 **实际数据流量**

|类型|发送内容|特点|
|---|---|---|
|**Distance Vector**|发送 “到 d 的距离”|仅知道代价，不知道完整路径；易出现环路|
|**Path Vector**|发送 “到 d 的完整路径”|可检测环路，支持复杂策略|

- ✅ 避免 **count-to-infinity** 问题
- ✅ 支持灵活的路由策略（如选路偏好、过滤）
- ✅ 可实现 **loop detection**（路径中若出现重复 AS 则丢弃）

#### Flexible Policies（灵活策略）
- 每个节点可以应用本地策略
    - **Path selection**：选择哪条路径使用？
    - **Path export**：哪些路径对外通告？
##### 示例：
1. **Node 2 may prefer the path “2, 3, 1” over “2, 1”**
    - 即使“2→1”更短，Node 2 也可能因为带宽、可靠性等原因选择绕行“2→3→1”
    - 体现了 **业务导向的选路策略**
2. **Node 1 may not let node 3 hear the path “1, 2”**
    - Node 1 主动屏蔽某些路径信息，防止 Node 3 使用该路径
    - 体现 **策略控制能力**，可用于防攻击、限流、商业竞争等

#### BGP Operations (Simplified)
![[Pasted image 20260102153508.png]]
- 左侧流程图展示 BGP 的简化工作流程
- 右侧图示两个 AS（AS-1 和 AS-2）之间通过 BGP 会话连接
##### BGP操作流程
1. **Establish session on TCP port 179**
    - BGP 使用 TCP 协议，端口 179
    - 提供可靠传输（TCP 是面向连接的）
2. **Exchange active routes**
    - 会话建立后，双方交换当前活跃的路由表
    - 这是初始同步过程
3. **Exchange incremental updates**
    - 之后只发送变化的部分（增量更新）
    - 提高效率，减少带宽消耗
- BGP 是一种 **路径向量协议**，依赖于 AS-path
- BGP 不自动发现邻居，必须手动配置（静态或动态）
- BGP 支持 **多路径**、**策略路由**、**负载均衡** 等高级功能

### BGP消息
**BGP 是基于消息驱动的协议，四类消息构成了其完整通信流程**

| 消息类型             | 功能说明           |
| ---------------- | -------------- |
| **Open**         | 建立对等会话         |
| **Keep Alive**   | 定期心跳，维持连接      |
| **Notification** | 关闭或终止会话（错误时触发） |
| **Update**       | 宣告新路由或撤销旧路由    |
#### Open 消息
- 在 TCP 连接建立后发送
- 包含版本号、AS 号、保持时间（Hold Time）、BGP ID 等参数
- 用于协商双方配置是否一致

#### Keep Alive 消息
- 每隔一段时间（通常是 30 秒）发送一次
- 表示“我还活着”，防止连接超时断开
- 是一种轻量级的心跳机制

#### Notification 消息
- 当出现严重错误时发送（如版本不匹配、AS 不一致、认证失败）
- 接收方立即关闭 BGP 会话
- 是 BGP 的“异常终止”信号

#### Update 消息
- 最重要的消息类型
- 用于通告新的 IP 前缀（prefix）及其属性
- 或者撤销已知的路由（通过 `withdrawn routes` 字段）

#### 示例
- 一条 Update 消息可能包含：
    - 新增前缀：`192.0.2.0/24`
    - 属性：AS_PATH=\[65001,65002], NEXT_HOP=10.0.0.1, LOCAL_PREF=100
    - 撤销前缀：`198.51.100.0/24`

### BGP Attributes
**使用属性来选择“最佳路径”**
它让每个 AS 都能根据商业利益、性能需求制定自己的选路策略
#### LocalPref（本地优先级）
- 仅在 AS 内部传播（iBGP）
- 表示本 AS 中首选的出口路径
- **优先级越高越好**
- 可以覆盖默认的“最短 AS 路径”行为

#### Multi-exit Discriminator (MED)
- 用于影响外部邻居如何进入本 AS
- 类似于“建议值”，告诉邻居：“我这边这条路更优”
- 通常只在 eBGP 中有效，且不会被传递给其他 AS

#### Import Rules（导入规则）
![[Pasted image 20260102160649.png]]
- 三个方向输入路由：
    - 🔴 From Provider（上游供应商）
    - 🔵 From Peer（对等体）
    - ❤️ From Customer（客户）

|来源|特点|
|---|---|
|**Provider**|提供大量互联网可达性，通常是默认路由来源|
|**Peer**|对等体提供互补的路由，常用于优化性能|
|**Customer**|客户宣告自己的私有前缀，ISP 为其提供服务|
- 控制“我接受哪些路由？”
- 例如：
    - 只接受来自特定 AS 的前缀
    - 忽略某些 AS-path 的路由
    - 设置过滤策略避免环路或滥用

#### Export Rules（导出规则）
![[Pasted image 20260102160705.png]]
- 三个方向输出路由：
    - 🔴 To Provider（向上游上传）
    - 🔵 To Peer（对等体之间交换）
    - ❤️ To Customer（为客户服务）

| 方向              | 内容                                                    |
| --------------- | ----------------------------------------------------- |
| **To Provider** | 只导出 **客户和 ISP 自己的路由**（不导出对等体路由）  <br>→ 避免将对等体信息泄露给上级  |
| **To Peer**     | 导出 **客户和 ISP 路由**（通常不导出其他对等体的路由）  <br>→ 保持公平性和隐私      |
| **To Customer** | 导出 **全部路由**（包括来自 provider 和 peer 的）  <br>→ 让客户访问整个互联网 |


- 控制“我把哪些路由告诉谁？”
- 例如：
    - 不向对等体发布客户路由
    - 向提供商发布部分路由以赚取收入
    - 使用 Community 标签控制传播范围
### Hot Potato Routing
![[Pasted image 20260102160902.png]]
- 数据包从 Source 出发，进入一个 AS
- 路由器选择下一个跳点的标准是：**内部 IGP 路径最短**
- 目标是尽快把数据包“扔出去”（pass the hot potato）

#### 工作方式：
1. 当路由器收到一条 BGP 路由（比如去往 `192.0.2.0/24`），它知道下一跳是某个邻居
2. 但它不知道内部如何到达那个邻居
3. 所以它用 IGP（如 OSPF）计算到该邻居的最短路径
4. 选择 **IGP 距离最近的出口** 作为下一跳
- 数据包在源 AS 内快速转发，尽可能快地离开本 AS
	- 减少延迟
	- 提高吞吐量
	- 避免拥塞
	- 是 BGP 与 IGP 协同工作的体现
### Shortest AS Path != Shortest Path
![[Pasted image 20260102160728.png]]
- 左侧路径：**4 hops, 4 ASs**（经过 4 个自治系统）
- 右侧路径：**9 hops, 2 ASs**（经过 2 个自治系统）
**右边的路径更优！尽管跳数多，但 AS 数少**

- BGP 默认优先选择 **AS 路径最短** 的路径（即最少的 AS 数）
- 因为：
    - AS 越少 → 跨域越少 → 管理越简单
    - AS 越少 → 政策冲突风险越低
    - AS 越少 → 通常意味着更直接的互联
- 即使物理距离远、跳数多，只要 AS 数少，BGP 仍可能优选该路径

### Modeling BGP
#### 1. AS Relationships（AS 关系）
- **Customer/Provider（客户-提供商）**
    - 客户付费给提供商获取互联网接入
    - 提供商可以向客户宣告路由
- **Peer（对等）**
    - 双方互惠互利，互相交换路由
    - 通常无金钱交易
- **Sibling / IXP（兄弟/交换点）**
    - 大型 ISP 之间的对等，常见于 IXP（互联网交换点）

#### 2. Gao-Rexford Model（GR 模型）
- 一种简化模型，描述 AS 的路由偏好：
	-  **优先顺序：Customer → Peer → Provider**
		- 客户付款 → 优先使用客户路径
		- 对等免费 → 次之
		- 提供商收费 → 最后考虑

#### 3. Valley-Free Routing（无谷路由）
![[Pasted image 20260102161346.png]]
- 不允许路径出现“先上升再下降”的情况
- 例如：不能有 `C-P → P-P → P-C` 的模式
- 因为这会导致 **循环或不合理路径**

### AS Relationships: It’s Complicated
核心观点：
> **GR 模型虽然简洁，但在现实中过于理想化**

| 限制         | 说明                     |
| ---------- | ---------------------- |
| **严格层级**   | 每对 AS 只有一种关系，且对所有前缀都一样 |
| **忽略复杂现实** | 实际中存在多种混合关系            |
#### 现实世界的复杂性：

|现象|影响|
|---|---|
|**广泛对等（Widespread Peering）**|很多 ISP 直接对等，不再依赖传统层级|
|**按前缀对等（Per-prefix Peering）**|某些前缀对等，其他前缀仍走提供商|
|**Tier-1 被“超级巨无霸”取代**|如 Google、Amazon、Meta 等拥有全球基础设施，成为 de facto 的顶级网络|
|**IXPs 主导流量**|互联网交换点（IXP）承载了大部分流量，改变了路由格局|

### 其他BGP属性
#### 1. AS_SET
- 当一个 AS 有多个入口时，可以用 `AS_SET` 表示一组 AS
- 例如：`AS_PATH = {65001, 65002}` 表示这两个 AS 都可到达
- 不关心顺序，只表示集合
- 用于汇总多条路径，避免重复宣告

#### 2. Communities（团体）
- 任意数值标签，用于路由策略标记
- 例如：
    - `export only in Europe`
    - `do not export to peers`
- 通常在第一次跨域后就被剥离（stripped）
	- 防止策略被滥用
	- 保证安全性和可控性

#### 3. Prepending（前置）
- 在 AS_PATH 中多次添加自己的 ASN
- 例如：原本是 `[65001]`，变为 `[65001,65001,65001]`
	- 人为增加 AS 路径长度
	- 让其他 AS 认为这条路更“远”，从而不选它
	- 实现 **负载均衡** 或 **路径控制**
