# 以太网广播
- 定义：以太网最初设计为一种**共享信道、广播式的网络技术**。
	- 所有主机连接到一个**共享的物理信道**。
	- 任何一台主机发送的数据帧会被**所有其他主机接收**。
	- 主机通过检查帧中的**目的 MAC 地址**来判断是否需要处理该帧。
- 以太网技术
	- **10Base2（细缆以太网）** 旧技术
	- **Switch-based Ethernet** 新技术
		- 使用交换机（Switch）代替 Hub
		- 每个主机拥有独立的通信通道
		- 实现全双工、无冲突通信
		- 提高吞吐量和安全性
- 相关设备
	- **Hub（集线器）**
		- Hub 是一种**物理层设备（Layer-1）**，只能转发比特流，不理解数据帧内容。
		- 它将从任意端口收到的数据**广播到所有其他端口**（除了源端口）。
		- 所有连接到 Hub 的主机都处于同一个**冲突域（collision domain）**。
	- Hubs 和 Repeaters 都是 Layer-1 设备
		- 它们**不进行数据链路层或更高层的处理**。
		- 只负责**电气信号的再生与转发**。
		- 不会过滤流量、不识别 MAC 地址、不分割冲突域。

| 名称                      | 作用                                                                                                  |
| ----------------------- | --------------------------------------------------------------------------------------------------- |
| **Tee Connector（T型接头）** | 将计算机接入总线（bus），每个主机通过 T 型接头连接到主干电缆上。                                                                 |
| **Terminator（终端器）**     | 安装在总线两端，用于吸收信号反射，防止信号回波干扰（避免驻波）。                                                                    |
| **Repeater（中继器）**       | 用于延长网络距离，放大电信号，补偿衰减。它是**物理层设备（Layer-1）**。                                                           |
| **10Base2**             | 指的是使用**同轴电缆**的以太网标准：  <br>- **10 Mbps** 数据速率  <br>- **Baseband** 传输（基带）  <br>- **2** 表示最大段长约为 200 米 |


# Carrier Sense Multiple Access (CSMA)
是一种用于**共享通信信道**（如以太网、无线网络）的**媒体访问控制**（MAC），其核心思想是：
- **“先听后说”**（Listen Before Talk） 
- 设备在发送数据之前，先**侦听信道是否空闲**，只有在信道空闲时才尝试发送，以**减少冲突**（collision）。
##  基本工作原理
1. **侦听信道**（Carrier Sense）
    - 主机准备发送数据前，先检测物理信道上是否有其他设备正在传输信号（即是否存在“载波”）。
    - 如果检测到信道**忙**（有信号），则**等待**；
    - 如果信道**空闲**，则**开始发送**。
2. **多路访问**（Multiple Access）
    - 所有主机共享同一信道，都有平等的机会使用它。
    - 没有中央控制器分配权限，属于**分布式协议**。
在早期的 ALOHA 协议中，主机可以随时发送数据，导致**冲突频繁、效率低下**（最大吞吐量仅约 18%）。  
CSMA 通过“先侦听”机制显著降低了冲突概率，提高了信道利用率。

尽管 CSMA 能减少冲突，但**不能彻底消除**，原因在于：
 **传播延迟**（Propagation Delay）
- 假设主机 A 和 B 相距较远。
- A 开始发送数据，但由于信号传播需要时间，B 在短时间内还“听不到”A 的信号。
- B 也认为信道空闲，于是也开始发送 → **两者信号在中间相遇，发生冲突**。

|协议|全称|核心机制|应用场景|
|---|---|---|---|
|**CSMA/CD**|Carrier Sense Multiple Access with **Collision Detection**|发送时**持续监听**，一旦检测到冲突立即停止发送，并发送“jam signal”，然后随机重试|**有线以太网**（如 10BASE-T、100BASE-T）|
|**CSMA/CA**|Carrier Sense Multiple Access with **Collision Avoidance**|通过**RTS/CTS 握手**、**退避算法**等方式**主动避免**冲突，而不是检测|**无线局域网**（Wi-Fi, IEEE 802.11）|
## CSMA 策略
### 1-persistent
- 站点有帧要发送时，**持续侦听信道**。
- **一旦发现信道空闲，立即发送**（概率为 1 → “1-persistent”）。
- 如果信道忙，则**继续侦听**，直到变为空闲。
**优点：**
- 延迟低（一空闲就发）
**缺点：**
- 冲突概率高：多个站点可能同时检测到信道变空闲，然后**同时发送** → 发生冲突

### Non-persistent
- 站点有帧要发送时，先侦听信道。
- 如果**信道空闲** → **立即发送**。
- 如果**信道忙** → **不持续侦听**，而是**随机等待一段时间后再重新侦听**。
**优点：**
- 冲突概率较低（避免多个站点同时抢发）
- 延迟较高（需等待）
**缺点:**
- 信道利用率可能较低：即使信道很快变空闲，站点也可能还在等待，造成**信道空闲浪费**

### p-persistent
- 时间被划分为固定长度的**时隙**（slot）。
- 当站点发现**信道在当前时隙开始时空闲**：
    - 以概率 **p** 在**当前时隙**发送；
    - 以概率 **(1−p)** **推迟到下一个时隙**再尝试。
- 如果信道忙，则等到下一个时隙重新判断。
**优点:**
- 在冲突和空闲之间取得**折中**
- 可通过调整 p 优化性能 
**缺点:**
- 需要时间同步（依赖时隙结构） 
- 实现稍复杂


| 策略                 | 信道空闲时的行为     | 信道忙时的行为     | 冲突概率  | 信道利用率 | 延迟    |
| ------------------ | ------------ | ----------- | ----- | ----- | ----- |
| **1-persistent**   | **立即发送**     | 持续侦听直到空闲    | **高** | 高     | **低** |
| **Non-persistent** | 立即发送         | **随机等待后重试** | **低** | 较低    | 高     |
| **p-persistent**   | 以概率 **p** 发送 | 等到下一时隙再判断   | 中等    | 中等    | 中等    |

# CSMA/CD (collision detection)
1. 在 CSMA/CD 中，站点在**发送数据的同时，能够监听信道状态**。这意味着它可以在发送过程中检测是否有其他站点也在发送信号。
2. 如果某个站点在发送时发现信道上出现了**额外的信号**（即另一个站点也在发送），就说明发生了**冲突（collision）**。冲突后，当前站点会：
	- **立即停止发送**（abort transmission）
	- 发送一个**jam signal**（填充信号），通知所有其他站点发生了冲突
	- 等待一段**随机退避时间**后重新尝试发送

一个站点如何才能确定自己已经成功“抢占”了信道？
- **只有当它完成了“最小冲突检测时间”之后，才能确认没有发生冲突。**

- _Minimum time to detect collision_ 
	- is the _time_ it takes for a signal to _traverse between two farthest apart stations._

## 抢占信道（seize the channel）
- 当一个站点成功发送数据帧，并且**网络中所有其他站点都接收到该帧的开始部分**时，就认为这个站点“抢占了信道”。
	- 在共享信道中，只有当所有设备都知道某个站点正在传输时，才能避免其他站点同时发送。
	- 这个过程依赖于信号传播时间与帧长度的关系。

## 最小帧长
- 为了确保 **冲突检测机制有效工作**，必须规定一个**最小帧长度**。
	- **冲突检测要求**：一个站点在发送过程中必须能够**在帧发送完成前检测到冲突**。
	- **最坏情况**：两个相距最远的站点（如 A 和 D）几乎同时开始发送。
	- **信号传播延迟**：从一端传到另一端需要时间 τ，往返时间为 2τ。
	- 因此，**帧的传输时间必须 $≥ 2τ$**，否则无法检测到冲突。
$$
Frame\;Transmission\;Time≥2×Propagation\;Delay
$$
## 以太网与CSMA/CD 协议
**传统以太网（如 10BASE-T、100BASE-T）采用 CSMA/CD 协议**，用于管理多个主机共享同一物理信道。
现代交换式以太网（Switch-based Ethernet）已不再使用 CSMA/CD，因为每个端口是独立通道，没有共享冲突域。

## 算法流程
1. **Sense for carrier（侦听载波）**
- 主机检查信道是否空闲（是否有其他设备正在发送）。
- “载波”即指物理层的电信号。

2. **If carrier is present, wait for it to end**
- 若信道忙，则等待当前传输结束。
- 避免立即发送造成冲突和资源浪费。

3. **Send a frame and sense for collision**
- 一旦信道空闲，立即发送帧。
- 同时继续监听信道，看是否出现冲突（信号异常）。
	- 关键能力：**边发边听**（Transmit while listening）

4. **If no collision, then frame has been delivered**
- 如果整个发送过程中没有检测到冲突，说明帧成功发送。
- 其他站点都能接收到它（假设无错误）。

5. **If collision, abort immediately**
- 一旦检测到冲突（信号强度异常），立即停止发送。
- 并向信道发送一个 **jam signal**（填充信号），通知所有站点发生了冲突。
	- Make sure all hosts are aware of collision
	- Jam signal is 32 bits long (plus header overhead)

6. **Perform exponential backoff then retransmit**
- 使用 **二进制指数退避算法**（Binary Exponential Backoff）：
    - 初始重试次数为 0。
    - 每次失败后，随机选择一个时间间隔 $k \in [0,2^k−1]$个时隙（slot time）进行等待。
    - n是冲突的数量
    - k 是重试次数，最多 10~16 次。
- 随着重试次数增加，等待时间呈指数增长，减少再次冲突的概率
- 每个“时间单位”称为一个 **contention slot**（争用时隙），长度等于发送一个最短帧所需的时间（如 512 比特 / 10 Mbps = 51.2 μs）
- 如果经过 **16 次冲突**仍未成功发送，则放弃该帧，报告传输失败
### Contention Slots
- 是一个**标准化的时间单位**，用于量化退避时间。
- 长度等于发送一个最小帧（64 字节）所需的时间。
- 在 10 Mbps 以太网中约为 **51.2 微秒**
- 提供统一的时间基准，便于同步不同设备的行为
- 避免精确计时带来的复杂性
- 使得退避过程更加公平、可预测

|概念|解释|
|---|---|
|**CSMA**|先听后说，避免盲目发送|
|**CD**|边发边听，及时发现冲突|
|**Seize the channel**|成功让所有站点知道你正在发送|
|**Minimum frame length**|确保冲突能在发送完成前被检测|
|**Exponential backoff**|减少重复冲突，提高效率|
|**Jam signal**|通知所有站点发生了冲突|

## 最小包大小（64bytes）
最小包大小为64字节的原因是：**为了确保在最远的两个主机之间发生冲突时，发送方能够在发送完成前检测到冲突。**
因为**如果帧太短，可能还没发完，就已经被其他站点干扰了，而发送方却无法察觉！**
![[Pasted image 20251229205629.png]]
1. Time $t$: Host A starts transmitting
2. Time $t + d$: Host B starts transmitting
3. Time $t + 2*d$: collision detected
**A 必须在$t+2d$ 时刻仍然在发送数据**，否则无法检测到冲突！
### 计算最小帧大小的公式
$$
Min_{pkt}=rate×2×d = \frac{rate*2*distance}{speed\;of\;light}
$$
其中：
- `rate`：链路速率（单位：bps，比特每秒）
- `d`：单向传播延迟（单位：秒）
	- $d=\frac{distance​}{speed\;of\;light}$
最小帧大小取决于：
- 网络带宽（rate）
- 电缆长度（dist）
- 信号传播速度（light speed）
$$
Dist = min_{pkt}  * light\;speed /(2 * rate)
$$

### 最大的包大小
Maximum Transmission Unit (MTU): 1500 bytes
- 是网络接口在一次传输中能够发送的最大数据包大小（单位：字节）
- Pros:
	- Bit errors in long packets incur significant recovery penalty
- Cons:
	- More bytes wasted on header information
	- Higher per packet processing overhead
		- 虽然大帧减少了总包数，但每个包处理时需要更多 CPU 和内存资源（如缓存、DMA、中断处理等）。
- Datacenters shifting towards **Jumbo Frames**
	- 9000 bytes per packet
-  什么是 Jumbo Frame？
	- 一种扩展的以太网帧格式，允许单个帧携带 **超过 1500 字节的数据**
	- 常见大小：**9000 字节**（即 9KB）
	- 不再受限于传统 MTU，适用于高速、低延迟的环境
- 整个以太网帧还包括：
    - 前导码（Preamble）：8 字节
    - 目的 MAC 地址：6 字节
    - 源 MAC 地址：6 字节
    - 类型/长度字段：2 字节
    - 数据部分（Payload）：最多 1500 字节
    - FCS（帧校验序列）：4 字节

## 现代Ethernet
- 现代以太网基于**交换机（Switch）** 的**点对点连接**架构。
- 尽管速度提升到 100 Gbps，但**以太网帧格式保持不变**！
- 全双工通信：
	- 主机可以**同时发送和接收数据**
	- 不再需要“先听后说”或“边发边听”
	- 因此，**不再需要 CSMA/CD**
- 在交换式网络中，每个端口是独立链路，不会发生冲突 → **无需检测冲突**
- **Auto negotiating (backwards compatibility)**
	- 设备之间开机时自动协商：
    - 最大支持速率（10/100/1000/10000 Mbps）
    - 是否支持全双工
    - 是否支持 PoE（供电）
- 举例：
	- 一台电脑连接到交换机：
	    - 如果电脑只支持 100 Mbps，交换机会降速运行
	    - 如果支持 1 Gbps，则自动升级至 1 Gbps 全双工
以太网供电（PoE, Power over Ethernet）
- 通过标准以太网电缆（如 Cat5e/Cat6）传输电力
- 支持设备：IP 摄像头、无线 AP、VoIP 电话、传感器等

|标准|功率|应用场景|
|---|---|---|
|PoE (802.3af)|15.4W|IP 电话、摄像头|
|PoE+ (802.3at)|30W|PTZ 摄像头、瘦客户端|

###  Bridging（跨网络）
**桥接（Bridging）** 是一种用于**连接两个或多个局域网（LANs）** 的技术，使得它们可以像一个单一的网络一样通信。

使用 **Bridge（桥接器，数据链路层设备）** 或 **Switch（交换机）** 连接两个LAN
#### 重要功能
1. **帧转发（Forwarding of frames）**
2. **MAC 地址学习（Learning of MAC Addresses）**
3. **生成树算法（Spanning Tree Algorithm, STP）——用于处理环路**
#### 桥接器的功能
| 功能            | 说明                              |
| ------------- | ------------------------------- |
| **学习 MAC 地址** | 观察每个端口上收到的帧，记录源 MAC → 端口号映射表    |
| **转发帧**       | 查找目标 MAC 是否在本地网段；若不在，则转发到其他 LAN |
| **过滤流量**      | 如果目标在同一个 LAN，不转发 → 减少广播风暴       |
#### Plug-and-play, self configuration
桥接器应能**自动发现网络拓扑**，无需人工配置。
- 使用 **STP（Spanning Tree Protocol）**：自动构建无环树形结构
- 自动学习 MAC 地址表（通过监听流量）
- 支持热插拔设备（即插即用）

#### How to resolve loops
**生成树协议（Spanning Tree Protocol, STP）**
- 由 IEEE 802.1D 定义
- 动态选择一条主路径，阻塞冗余链路
- 当主路径失效时，自动启用备用路径
- 实现“**逻辑无环，物理冗余**”
#### 转发表
 每个桥接器维护一张 **转发表（Forwarding Table）**

|列名|含义|
|---|---|
|**MAC Address**|目标设备的物理地址|
|**Port**|该设备连接的桥接器端口号|
|**Age**|条目最后更新时间（用于老化删除）|
![[Pasted image 20251230134252.png]]

#### 桥接多个LAN的目的
- **用桥接器（Bridge）将多个局域网连接起来，并分割冲突域**
- 将一个大型广播网络划分为多个较小的 **碰撞域（Collision Domain）**
- 每个桥接器端口是一个独立的冲突域

#### MAC地址学习
**观察每个帧的源 MAC 地址及其到达的端口**
- 主机 A 发送帧 → 从 Port 1 到达 → 桥接器记录：`A → Port 1`
- 主机 B 发送帧 → 从 Port 2 到达 → 桥接器记录：`B → Port 2`
- 老化机制（Timeout）：
	- 设置一个超时时间（如 5 分钟），如果某个 MAC 地址长时间未出现，则将其条目删除。

## 从 Hub 到 Bridge 的进化之路

| 项目         | Hub（集线器）     | Bridge（桥接器）    |
| ---------- | ------------ | -------------- |
| **工作层次**   | 物理层（Layer 1） | 数据链路层（Layer 2） |
| **功能**     | 放大信号，广播所有帧   | 智能转发，基于 MAC 地址 |
| **冲突域**    | 整个网络为一个冲突域   | 每个端口为一个独立冲突域   |
| **扩展性**    | 差（主机增多导致混乱）  | 强（可连接多个 LAN）   |
| **智能程度**   | 低（被动复制）      | 高（学习、过滤、STP）   |
| **是否支持环路** | 不支持（无机制）     | 支持（STP 防止广播风暴） |

### 广播风暴和生成树算法
#### 环路的危险：广播风暴
**同一个帧被无限次复制和传播** 
- 网络中有多个桥接器（或交换机）形成一个**闭环拓扑**
- 主机 AA 发送一个帧 `<Src=AA, Dest=DD>`
- 由于存在多条路径，该帧在环中不断循环转发

使用 **生成树算法（Spanning Tree Algorithm）** 动态构建一棵无环的“树形”拓扑结构，实现逻辑上的无环网络。**保留一条路径，阻塞其他冗余路径**。

#### 生成树
**生成树（Spanning Tree）是图中的一组边的子集，满足两个条件：**

1. **覆盖所有节点（Span all nodes）**
    - 每个设备都能连通到网络
2. **不产生任何环路（Do not create any cycles）**
    - 无循环路径，防止广播风暴
3. **选举一个根桥（Root Bridge）**
4. **每个桥计算到根桥的最短路径**
5. **这些路径的并集构成生成树**

- 桥之间交换 **配置桥协议数据单元（Configuration BPDU）**
- BPDU 包含关键信息用于决策
	- 选举根桥
	- 计算路径成本
	- 确定下一跳和端口状态
	- 决定哪些端口应启用/阻塞

 **BPDU 的组成字段：**

| 字段                    | 含义                        |
| --------------------- | ------------------------- |
| **Bridge ID**         | 当前桥的标识符（通常是 MAC 地址 + 优先级） |
| **Root ID**           | 当前认为的根桥 ID（初始为自己）         |
| **Path Cost to Root** | 到根桥的路径总成本（单位：端口成本）        |
#### 选举规则（基于收到的 BPDU）：
每台桥根据收到的 BPDU 更新以下内容：
1. ✅ **新的根桥（Root Bridge）**  
    → 选择 **Root ID 最小** 的那个（数值越小越优）
    
2. ✅ **新的根端口（Root Port）**  
    → 本桥上通往根桥路径**成本最低**的端口
    
3. ✅ **新的指定桥（Designated Bridge）**  
    → 在某个网段上，负责转发数据到根桥的桥（通常是离根最近的那个）


### 现代交换机
交换机是现代局域网的核心设备，具备以下三大功能：
1. **基于 MAC 地址的全网路由（Network-wide routing based on MAC addresses）**
    - 通过学习源 MAC 地址，构建转发表
    - 根据目标 MAC 地址决定转发端口
2. **自动学习新主机的路径（Learn routes to new hosts automatically）**
    - 不需要人工配置
    - “即插即用”（Plug-and-play）
    - 支持动态变化的网络环境
3. **解决环路问题（Resolve loops）**
    - 使用生成树协议（STP）阻塞冗余链路
    - 防止广播风暴和无限循环

#### 能否把整个互联网变成一个“交换域”？
虽然交换机在局域网中表现优异，但将其扩展到全球互联网是**不可行的**。
**因为，MAC 地址交换机制存在根本性的可扩展性缺陷**。

### MAC交换机的局限性
 1. **效率低下（Inefficient）**
	- 当交换机不知道某个 MAC 地址时，会进行 **泛洪（Flooding）**
		- 即将帧发送到所有端口（除接收端口外）
	- 在大型网络中，会导致大量不必要的流量
 2. **性能差（Poor Performance）**
	- **生成树不均衡负载**（Spanning tree does not balance load）
	    - 只保留一条路径，其他路径被阻塞
	    - 导致某些链路过载，形成“热点”（Hot spots）
	- 缺乏多路径优化机制
3. **极差的可扩展性（Extremely Poor Scalability）**
	- 每个交换机必须存储**全网所有主机的 MAC 地址**
	- 全球约有数十亿台设备，每台都有唯一的 MAC 地址

- 如果每个交换机都要维护如此庞大的表项，后果如下：

| 问题      | 影响               |
| ------- | ---------------- |
| 🧠 内存不足 | 无法容纳海量 MAC 表     |
| ⏱️ 查找延迟 | 大量表项导致查找速度变慢     |
| 💾 存储成本 | 每台设备都需要巨大内存      |
| 🔁 更新困难 | 主机移动或更换设备时，需全局同步 |
# IP 的优势（跨本地网络）

|问题|MAC 交换的问题|IP 的解决方案|
|---|---|---|
|**可扩展性**|每台交换机需知道所有 MAC|IP 使用分层寻址（如子网、自治系统），只需知道“下一跳”|
|**路由规模**|全网 MAC 表过大|路由器只维护路由表（如 /24 网段），而非单个主机|
|**跨网络通信**|MAC 仅限本地广播域|IP 支持跨网络转发，支持全球路由|
|**动态变化**|MAC 学习依赖本地流量|IP 路由协议（如 OSPF, BGP）可动态更新路径|
