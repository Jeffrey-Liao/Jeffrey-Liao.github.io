# Network Layer Overview
# 概述
工作原理：
- Route packets end-to-end on a network, through multiple hops

解决的主要问题：
1. **异构网络互联（Internetworking）**
	- 引入**统一的逻辑地址（IP 地址）** 和 **通用分组格式（IP 数据报）**，屏蔽底层差异。
2. **可扩展性（Scalability）**
	- 采用 **层次化编址 + 路由聚合（Route Aggregation）**
		- IP 地址具有结构（如 `192.168.1.0/24` 表示一个子网）
		- 路由器只需知道“去往某网段”的下一跳，而非具体主机
		- 例如：一条路由 `192.168.0.0/16` 可覆盖 65536 个 IP
3. **动态路径选择与容错（Dynamic Routing & Fault Tolerance）**
	- 静态配置不现实（拓扑变化频繁）
	- 需要自动发现邻居、计算最短路径、快速收敛

使用 **动态路由协议**，分为两类：

|类型|协议示例|适用场景|
|---|---|---|
|**内部网关协议（IGP）**|OSPF, RIP, IS-IS|自治系统（AS）内部|
|**外部网关协议（EGP）**|BGP|自治系统之间（如 ISP 互联）|

# 路由和互联网络
## 路由器：连接多个局域网的关键设备
- 每个局域网内部由交换机（Switches）连接主机
- 多个局域网通过 **路由器（Routers）** 相互连接

- 不同的**局域网**可能使用不同的技术：
    - Ethernet（以太网）
    - Wi-Fi（无线局域网）
    - Token Ring、FDDI 等
- 协议、帧格式、传输速率都可能不同
- 当多个 LAN 被路由器连接后，它们就构成了一个 **互联网络（Internetwork）**

**全球互联网就是最大的互联网络**
- 它由数百万个局域网通过路由器连接而成
### Naming / Addressing（命名与寻址）
**IP 地址（IPv4 / IPv6）**
- 每台主机有一个全局唯一的逻辑地址
- 例如：`192.168.1.1` 或 `2001:db8::1`
- 域名系统（DNS）提供名称到 IP 的映射（如 `www.google.com → 142.250.185.100`）

### 路由
**Must be scalable（必须可扩展）**
- 必须支持动态、自动化的路径发现
- 解决方案：**动态路由协议**
    - IGP：OSPF、RIP（用于自治系统内）
    - EGP：BGP（用于自治系统间）

### Service Model
定义了网络能提供什么服务，以及如何应对不确定性
**让网络尽可能简单，把复杂性留给端系统**（这就是著名的 **端到端原则（End-to-End Principle）**）
- 发送数据包
- 速度会尽力而为，无 QoS 保证
- 如果发生错误，分组可能丢失、延迟、乱序
- 不同的网络速度、可靠性、MTU等都可能不同

# 互联网服务模型
互联网的设计原则是：**在所有异构网络中都能工作，即使功能最弱的那个也能支持**
- **不保证数据一定送达**
- **不保证顺序、不保证延迟、不保证带宽**
- 如果丢包或失败，由上层协议（如 TCP）处理
- 传输时
	- 数据以“分组”（datagram）形式发送
	- 每个分组独立路由，可能走不同路径
	- 路由器收到后**先存储再转发**（store-and-forward）
	- 无连接（connectionless），无需建立会话

# 寻址
## Flat（扁平地址）
每个主机使用一个**全局唯一**的标识符，没有层次结构。
- **MAC 地址**：48 位，全球唯一，由厂商分配
- 格式如：`00:1A:2B:3C:4D:5E`
- 扁平地址适用于**局域网（LAN）内通信**（如交换机学习 MAC），但**不适合全球互联网**。

## Hierarchy（分层地址）
将地址划分为多个部分，**每一部分代表不同的抽象层级**。
- 地址被分解为 **段（segments）**
- 每个段具有**不同级别的具体性**（specificity）
- 越前面越通用，越后面越精确
### 分层优势：
- **Updates are Local**：如果某个用户换号，只需更新本地交换机，不影响全国系统
- **路由高效**：长途电话先按国家→区号→交换机逐级转发
- **可扩展性强**：新增城市只需分配新区号，无需改变整个体系
### 二进制分层（Binary Hierarchy）
- 使用二进制地址（如 3 位）构建树状结构
- **每个节点**表示一个**子网或路由器**
- 路由器根据前缀进行转发决策

![[Pasted image 20251230182742.png]]
目标地址 = `101`
1. 根路由器看到前缀是 `1` → 发往左侧网络（蓝色云）
2. 下一级路由器看到前缀是 `10` → 发往子网 `10*`
3. 再下一级：`101` 是终端主机 → 直接送达
### 寻址规则
- **前缀匹配（Prefix Matching）**：路由器只关心地址的前几位
- **长前缀优先（Longest Prefix Match）**：如果有多个匹配，选最长的
- **聚合（Aggregation）**：例如 `10*` 可以代表两个主机，减少路由表条目
# IP概述
## IP地址
- IPv4：32 位地址
	- 总共约 $2^{32}$≈43 亿个地址
	- 通常写成 **点分十进制格式（dotted decimal notation）**
	- 示例：`192.168.21.76`
		- Decimal: 192.168.21.76
		- Hex: C0.A8.15.4C
		- Binary: 11000000.10101000.00010101.01001100
	- 每个数字是 **1 字节（8 位）**

## IP 寻址与转发（IP Addressing and Forwarding）
### 分层地址结构
![[Pasted image 20251230183621.png]]
- **Pfx（Prefix）**：标识网络等级（如 /24）
- **Network**：标识哪个网络（如 192.168.21）
- **Host**：标识该网络中的哪台主机（如 .76）

| 信息                | 谁知道？                 | 说明      |
| ----------------- | -------------------- | ------- |
| **Network + Pfx** | 所有路由器都知道             | 用于跨网络路由 |
| **Host**          | 边缘路由器（接入 LAN 的路由器）知道 | 仅需在本地查找 |
**优势：**
- 大型核心路由器只需维护“网络”级别的路由表
- 减少内存占用，提升查找速度
- 支持路由聚合（如将 192.168.0.0/24 到 /24 的多个网络合并为一条路由）

### IP地址分类
**早期** IPv4 使用 **分类地址（Classful Addressing）**，虽然已被 CIDR 取代，但仍是理解历史的重要基础。

| 类别          | 前缀    | 网络位数 | 主机位数 | 用途          | 示例            | 前缀范围    |     |
| ----------- | ----- | ---- | ---- | ----------- | ------------- | ------- | --- |
| **Class A** | `0`   | 8 位  | 24 位 | 大型机构（如 MIT） | `18.*.*.*`    | 1-126   |     |
| **Class B** | `10`  | 16 位 | 16 位 | 中型企业（如 NEU） | `129.10.*.*`  | 128-191 |     |
| **Class C** | `110` | 24 位 | 8 位  | 小型组织或家庭     | `216.63.78.*` | 192-223 |     |
- 第一个字节决定类别
- 网络号和主机号长度固定
**缺陷：**
- **浪费严重**：比如 Class A 可容纳 1600 万台主机，但很少有组织需要这么多
- **缺乏灵活性**：不能按需分配大小合适的地址块

#### CIDR（Classless Inter-Domain Routing）
- 使用变长前缀（如 `/24`, `/26`）
- 更灵活地分配地址
- 支持路由聚合，减少路由表大小

## 如何获取IP
**IP address ranges controlled by IANA (Internet Assigned Number Authority)** 目前隶属于**ICANN**（Internet Corporation for Assigned Names and Numbers，互联网名称与数字地址分配机构）
该机构负责
1. **IP 地址分配**
2. **域名系统**（DNS）
	- 通用顶级域（gTLD）：`.com`, `.org`, `.net`, `.xyz`, `.shop` 等
	- 国家代码顶级域（ccTLD）：`.cn`（中国）、`.uk`（英国）、`.jp`（日本）等
	- 认证域名注册商（Registrar），如 GoDaddy、阿里云、Namecheap
3. **根服务器系统管理**
	- 协调全球 **13 组 DNS 根服务器**（实际有上千个镜像节点）
	- 这些根服务器是 DNS 查询的起点，回答“`.com` 的权威服务器在哪里？”等问题
	- 虽然根服务器由不同机构（如 Verisign、NASA、ISC 等）运行，但其配置需经 ICANN 协调

## 子网划分和IP地址构建
### 分类地址

| 类别  | 前缀位数 | 网络位数 | 网络数量   | 每网络主机数 |
| --- | ---- | ---- | ------ | ------ |
| A   | 1    | 7    | 126    | ~1670万 |
| B   | 2    | 14   | 16,398 | ~6.5万  |
| C   | 3    | 21   | 209.7万 | 254    |
**分类地址系统过于粗粒度（coarse-grained）**，既不能灵活分配，也无法有效利用资源。

### 子网划分（Subnets）
**增加一层层级 → 引入“子网”（Subnet）**
![[Pasted image 20251230204437.png]]
- **外部看**：仍然是一个单一网络（如 `128.42.0.0/16`）
- **内部看**：可以划分为多个子网（如 `/24`, `/26` 等）
#### 子网掩码（Subnet Mask）
- 用于区分哪些位属于“网络+子网”，哪些属于“主机”
- 示例：`255.255.128.0` → 二进制为 `11111111.11111111.10000000.00000000`
- 表示前 17 位是网络+子网部分，后 15 位是主机
-  使用按位与（AND）操作提取子网操作信息
1. **提取网段信息**
![[Pasted image 20251230204613.png]]
 得到网络地址：`181.213.64.0`
 2. **提取主机信息**
![[Pasted image 20251230204641.png]]
 到主机地址：`0.0.20.114`
#### N 层子网层次结构（N-Level Subnet Hierarchy）
从两层 → 多层子网
![[Pasted image 20251230210328.png]]
- **树没有固定深度**（Flexible Depth）
- **子网掩码越来越具体**（如 `/24`, `/26`, `/28`）
- **子树大小由子网掩码长度决定**
![[Pasted image 20251230210427.png]]
**优势：**
- 更灵活地适应不同规模的网络（如部门、楼层、房间）
- 支持 **VLSM（可变长子网掩码）**
- 减少广播域，提升安全性与性能

**子网划分改善了局部管理，但未根本解决全局可扩展性问题**

| Address Pattern | Subnet Mask   | Destination Router |
| --------------- | ------------- | ------------------ |
| 0.0.0.0         | 0.0.0.0       | Router 4           |
| 18.0.0.0        | 255.0.0.0     | Router 2           |
| 128.42.0.0      | 255.255.0.0   | Router 3           |
| 128.42.128.0    | 255.255.128.0 | Router 5           |
| 128.42.222.0    | 255.255.255.0 | Router 1           |
**最长前缀匹配（Longest Prefix Matching）**
- 找出 **子网掩码中 1 最多** 的那一行
- 因为它代表最具体的路由

### CIDR（Classless Inter-Domain Routing）
**CIDR 是对旧式分类系统的彻底改革——它让地址分配更高效、路由更可扩展。**
- 使用 **斜线表示法**（如 `192.168.1.0/24`）
- `/24` 表示前 24 位是网络前缀，后 8 位是主机
- 可以**灵活**分配任意大小的地址块（如 `/6`, `/28`）
- 支持路由聚合（Aggregation），极大减少路由表条目

|概念|说明|
|---|---|
|**1. 废弃 IP 类别（Get rid of IP classes）**|不再使用 A/B/C 类划分，而是根据实际需求灵活分配地址块|
|**2. 使用位掩码进行所有层级的路由（Use bitmasks for all levels）**|所有网络都用子网掩码或前缀长度表示，实现统一处理|
|**3. 聚合（Aggregation）以最小化 FIB（Forwarding Information Base）**|将多个小网络合并为一个大条目，减少路由表大小|

#### 聚合
示例：
- 获得范围：`207.46.192.*` 到 `207.46.255.*`
- 共包含：`2^6 = 64` 个 Class C 网络（从 `.192` 到 `.255`）
- 传统方式需 64 条路由
- CIDR 方式只需 **1 条路由**！
- 使用这些网络的公共子前缀作为掩码

CIDR 表达：`207.46.192.0/18`

|字段|含义|
|---|---|
|`207.46.192.0`|网络前缀|
|`/18`|前 18 位是网络部分，后 14 位是主机|
**重要意义：**
- **CIDR 成功控制了路由表的增长速度**
- 即使互联网用户激增，路由表也未失控
- **只有骨干路由器需要维护完整路由表**

### 总结
 1. **层次化寻址是可扩展性的关键**
	- 不是所有路由器都需要知道全部细节
	- 只有少数核心路由器需要感知变化

2. **非均匀层次结构适用于异构网络**
	- 传统分类地址太粗粒度（Class-based too coarse）
	- CIDR 允许灵活划分 → 更适合不同规模的组织
	- 支持 VLSM（可变长子网掩码）、路由聚合等高级功能

3. -**最长前缀匹配（Longest Prefix Matching）** 比简单匹配更复杂
    - 必须在海量路由中快速找到最具体的匹配项
    - 对硬件（如 TCAM）和算法要求高
    - 是现代路由器的核心技术难点之一

**CIDR 是 IPv4 生命延续的关键技术**。它不仅解决了早期地址分配不均的问题，还通过路由聚合显著减缓了路由表膨胀的速度，支撑了互联网从几十万用户发展到数十亿用户的巨大跃迁。
