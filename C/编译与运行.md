# 从文件到软件
## C语言的文件分类
### 代码文件
![](pic/Pasted%20image%2020260116093803.png)
当你在编写代码的时候，C语言有两种格式的文件：
- `.h`：header file，头文件，大多用于存储**声明**
- `.c`：source file，源文件，大多用于存储**定义**

这两个文件都可以同时存在多个，且存**放在硬盘**上。但在第一章我们说过，CPU主要读取的是内存
，因为硬盘太慢了，所以我们就会有将他们**载入内存进行操作**的过程。

**头文件：**
![](pic/Pasted%20image%2020260116095353.png)
- **只包含叫什么**
- 不包含是什么

**源文件：**
![](pic/Pasted%20image%2020260116095442.png)
- 包含对头文件中声明的定义（是什么，也就是和`I(),love(),you()`对应的实际操作）
- **不能在没有定义的情况下使用函数**，因为计算机只知道这个东西叫什么，但还不知道是什么。就像我不能把现在只是知道有C语言，Java语言的你直接送去公司上班吧。




### 可执行文件
**可执行文件**是一组**二进制指令**（其实就是二进制数字，不过操作系统和CPU以及其他硬件设备之间建立了一个映射关系，把某些识别为数字，某些识别为指令）。

在**不同操作系统**下的**可执行文件后缀不同**，**也不通用**。你把安卓手机上的可执行文件安装到Windows电脑上是不可能的（虽然使用例如Window Subsystem for Android的虚拟机技术可以安装并使用，但Windows本身不支持）。

- `.exe`：Windows系统的可执行文件
- `.out/.bxy/啥都没有`：在*macOS*和*Linux*系统中，可执行文件的扩展名可以是任意的，甚至可以没有扩展名】

在执行可执行文件的时候，操作系统会为可执行文件**分配一个内存空间**，这个空间是**理论上无限的**。且不同的**软件之间相互隔离**，除非使用操作系统允许的方式进行通信。

### 其他文件
#### 库文件
库文件是**操作系统**提供的一些**内置的预定义操作库**（如输出，输入，详见**常见库函数**）。这样我们就**不用**费劲地去**实现一些很简单的功能**，例如输入输出（其实这俩看似简单，如果要自己写非常复杂）。

所以在你使用例如`<stdio.h>,<stdlib.h>`等头文件的时候（这些就是操作系统库）。在**编译的过程**中，编译器会把**库文件也载入内存**，让库文件实现库的功能（如`printf,scanf`）。

在操作系统下还分
- `lib/a`：静态库文件(Windows/Linux)
- `dll/so`：动态库文件(Windows/Linux)

#### 自定义文件
在你写代码的长路上，读写文件是你必须要去做的事情。也就是把你程序的数据存在电脑上。

之前我们就说过，内存是易失的，一断电就数据清零了。但是有时候我们又有**记忆数据的需求**，这时候就需要在硬盘上创建一个文件并对其进行读写以**保存我们的数据**。

自定义文件的格式由你自己决定，后缀也是。

不过现在由于标准化的发展，有这样通用标准的文件格式可以被使用。
- json（**JavaScript Object Notation**）：常用于网络数据传输，应用或配置文件存储
- yml：常用于各种配置文件中

## 生成可执行文件
我们写的代码是没有意义的，只有把它**变成能跑的应用程序**（可执行文件）才是有意义的。而**生成可执行程序的过程（一般口语化叫做编译，但是它其实有很多个步骤）是个很复杂的操作**，尤其是编译这个环节，这个等之后编译器原理的时候再给你介绍更多吧。

**下面所有的"编译"除了在编译环节代表编译以外，其他都是代表生成可执行文件的整个过程**（主要大家都已经习惯这么说了捏）

此外，**每个语言的编译过程都是不一样的**，这里展示的是C和C++的编译过程。

#### 预处理
1. C语言的编译器会将本文件所引用的**头文件按照顺序粘贴到当前源代码**的前面。
2. C语言的编译器会**将所有的宏替换**。

下面展示了一个简单的例子，当一个原文件有两个头文件`test.h`和`header.h`时，预处理器如何处理
```C
//headers
// test.h
#define HELLO 10
void function();
int love();
void you();

// header.h
void I();
void suki();


//source
#include "test.h"
#include "header.h"
int love()
{
	printf("love");
	return 52;
}
void you()
{
	printf("you");
}
void I ()
{
	printf("I");
}
void function()
{
	I();
	int n = HELLO;
	n = n * love();
	
	if(n == 520)
	{
		you();
	}
}
```

经过预处理后的代码如下:
```C
void function();
int love();
void you();
void I();
void suki();
int love()
{
	printf("love");
	return 52;
}
void you()
{
	printf("you");
}
void I ()
{
	printf("I");
}
void function()
{
	I();
	int n = 10;
	n = n * love();
	
	if(n == 520)
	{
		you();
	}
}
```
预处理进行了以下两个操作：
- 将所有的函数声明粘贴到了当前文件下
- 替换`HELLO`为10
	- `HELLO`叫做**宏常量**，就是一个不变量，当在代码中出现它时等价于出现它后面的东西（实际上编译器进行的也是**将`HELLO`替换为`HELLO`后面的字面量**）

#### 编译
编译分为多个步骤，且每个步骤都非常复杂。这里只做简要介绍，更难的我在编译器原理中写给你( •̀ ω •́ )✧。

##### 1. 语法分析（Parsing）
>对代码上的某些部分按照语法成份进行标记。
```c
int n = 0;
```
变成⬇️
```
int(关键字) n(标识符) =(运算符) 0(数据字面量)
```

##### 2. 语法检查（Syntax check）
>检查语法是否正确，例如
```C
int a = 0; //correct
itn a = 0;//incorrect 没有itn这个关键字

int int = 0;//错误！int是关键字，不能作为变量名称
int a;//错误！已经存在一个叫做a的变量。
```

##### 3. 语义检查（Semantic check）
>检查给予某些变量的值是否正确
```c
int a = "毕小宇我爱你";//错误！不能给字符型字面量赋值给int
int b = 1020;
const char* s = "I love you";
b = s;//错误！不能把const char* 类型的变量赋值给int,C语言没有定义这种转换关系
```

##### 4. 汇编（代码生成）
>如果代码成功通过了刚刚的所有检查，就生成汇编语言代码，并由操作系统打包为一个可执行程序

#### 链接(link)
在编译时，如果使用了库文件中的代码（如：`printf`，你的代码里只有我使用了`printf`，但没有`printf`实际实现功能的代码，这些代码在库文件中），代码中只有一个使用，没有函数的定义。

这时候编译器就会留下一个“这里使用了库函数`printf`”的留言。链接器就会将这句话和实际的`printf`的功能代码链接起来，让库文件和当前代码协同工作。
