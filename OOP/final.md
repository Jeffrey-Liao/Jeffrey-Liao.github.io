| 图类型                                  | 用途                           |
| ------------------------------------ | ---------------------------- |
| **用例图（Use Case Diagram）**            | 描述系统功能与外部参与者（Actor）的交互       |
| **类图（Class Diagram）**                | 展示类、属性、方法及类间关系（关联、聚合、组合、继承等） |
| **对象图（Object Diagram）**              | 类图的实例化，展示某一时刻的对象及其链接         |

| **协作图 / 通信图（Communication Diagram）** | 强调对象间的结构关系与消息流               |
| **状态图（State Machine Diagram）**       | 描述对象在其生命周期中的状态变化             |
| **活动图（Activity Diagram）**            | 类似流程图，表示业务流程或算法逻辑            |
| **组件图（Component Diagram）**           | 描述系统模块化结构及依赖                 |
| **部署图（Deployment Diagram）**          | 表示软件在硬件环境中的部署情况              |
### 关系类型

- **关联（Association）**：对象之间的结构关系（如“学生选课”）。
	- 表示两个类之间存在某种**结构上的联系或协作关系**，是最通用的关系。例如：“学生选课”、“老师教课程”。
- **聚合（Aggregation）**：“整体-部分”关系，部分可独立存在（如“大学-学院”）。
	- 双方完全独立，无“整体-部分”语义。例如：`Student` 和 `Course` 可以各自独立创建和销毁。
- **组合（Composition）**：强聚合，部分不能脱离整体存在（如“房屋-房间”）。
	- 被组合类完全负责销毁和创建另一个类
- **依赖（Dependency）**：一个类使用另一个类（临时关系，如方法参数）。
	- 在函数中通过一个函数参数获得另一个类
- **泛化（Generalization）**：继承关系（如“Dog is a Animal”）。
- **实现（Realization）**：类实现接口。

### 设计模式（Design Patterns）

- 面向对象建模常结合经典设计模式，如：
    - 创建型：单例（Singleton）、工厂（Factory）
    - 结构型：适配器（Adapter）、装饰器（Decorator）
    - 行为型：观察者（Observer）、策略（Strategy）

### SOLID 原则（由 Robert C. Martin 提出）

表格

| 原则    | 全称                                    | 说明                                      |
| ----- | ------------------------------------- | --------------------------------------- |
| **S** | Single Responsibility Principle (SRP) | 一个类应该只有一个引起它变化的原因（即只负责一项职责）。            |
| **O** | Open/Closed Principle (OCP)           | 软件实体应对扩展开放，对修改关闭。通过继承或组合扩展行为，而非修改源码。    |
| **L** | Liskov Substitution Principle (LSP)   | 子类必须能替换其父类而不破坏程序正确性。                    |
| **I** | Interface Segregation Principle (ISP) | 客户端不应依赖它不需要的接口；应使用小而专注的接口。              |
| **D** | Dependency Inversion Principle (DIP)  | 高层模块不应依赖低层模块，二者都应依赖抽象；抽象不应依赖细节，细节应依赖抽象。 |

- **DRY（Don’t Repeat Yourself）**：避免重复代码。
- **KISS（Keep It Simple, Stupid）**：设计应尽可能简单。
- **YAGNI（You Aren’t Gonna Need It）**：不要过早添加未明确需要的功能。
- **高内聚（High Cohesion）**：类内部元素紧密相关。
- **低耦合（Low Coupling）**：类之间依赖尽可能少且松散。


### 一、单旋转（Single Rotation）

#### 1. **右旋（Right Rotation, RR）**

**适用场景**：在**左子树的左侧**插入节点，导致**左-左（LL）失衡**。

text

编辑

```
1       A                     B
2      / \                   / \
3     B   C     →→→         D   A
4    / \                       / \
5   D   E                     E   C
```

**操作步骤**：

- 将 A 的左孩子 B 提升为新根；
- B 的右子树 E 变成 A 的左子树；
- A 成为 B 的右孩子。


---

#### 2. **左旋（Left Rotation, LL）**

**适用场景**：在**右子树的右侧**插入节点，导致**右-右（RR）失衡**。

text

编辑

```
1   A                         B
2  / \                       / \
3 C   B         →→→         A   D
4    / \                   / \
5   E   D                 C   E
```

**操作步骤**：

- 将 A 的右孩子 B 提升为新根；
- B 的左子树 E 变成 A 的右子树；
- A 成为 B 的左孩子。
---

### 二、双旋转（Double Rotation）

当失衡发生在“外侧”时用单旋转，**发生在“内侧”时需双旋转**。

#### 3. **先左后右旋（Left-Right Rotation, LR）**

**适用场景**：在**左子树的右侧**插入节点 → **左-右（LR）失衡**

text

编辑

```
1     A                A                   C
2    / \              / \                 / \
3   B   D    →→→     C   D      →→→     B   A
4    \              /                   /   / \
5     C            B                   ... ... ...
```

**步骤**：

1. 对 B（A 的左孩子）执行**左旋**；
2. 对 A 执行**右旋**。

> 等价于：`rightRotate(A)` 前先 `leftRotate(A->left)`

---

#### 4. **先右后左旋（Right-Left Rotation, RL）**

**适用场景**：在**右子树的左侧**插入节点 → **右-左（RL）失衡**

text

编辑

```
1   A                A                    C
2  / \              / \                  / \
3 D   B    →→→     D   C        →→→    A   B
4    /                  \              / \   \
5   C                    B            ... ... ...
```

**步骤**：

1. 对 B（A 的右孩子）执行**右旋**；
2. 对 A 执行**左旋**。

> 等价于：`leftRotate(A)` 前先 `rightRotate(A->right)`



### BFS：使用 **队列（Queue）**

- **特性**：先进先出（FIFO, First-In-First-Out）
- **作用**：确保**先被发现的节点先被探索**，从而实现“按层”遍历。
- **工作过程**：
    1. 将起始节点入队；
    2. 出队一个节点，访问它；
    3. 将其所有**未访问的邻居**依次入队；
    4. 重复直到队列为空。

### DFS：使用 **栈（Stack）**

- **特性**：后进先出（LIFO, Last-In-First-Out）
- **作用**：支持“深入到底再回溯”的行为——最新发现的节点最先被继续探索。
- **实现方式**：
    - **显式栈**：手动维护一个栈（非递归实现）；
    - **隐式栈**：通过函数调用栈实现（递归实现）。


## 数据结构选择的深层原因

表格

| 算法      | 数据结构 | 为什么？                                    |
| ------- | ---- | --------------------------------------- |
| **BFS** | 队列   | 要保证“早发现的节点早处理”，才能按距离递增顺序探索，从而找到最短路径。    |
| **DFS** | 栈    | 要优先探索最新分支，模拟“深入→回溯”行为，栈的 LIFO 特性天然支持回溯。 |
