## 题目与答案

### 存储结构

1. 在Oracle数据库中，Table Space包含什么？
A. 若干个Data Blocks
B. 若干个Segments
C. 若干个Extents
D. 若干个Rows
**答案：B**
**解析：** Table Space是Oracle中最大的逻辑存储单元，包含若干个Segments。Segments由Extents组成，Extents由Data Blocks组成。

2. 每个表在Oracle中对应什么？
A. 一个Extent
B. 一个Data Block
C. 一个Segment
D. 一个Table Space
**答案：C**
**解析：** 每个表对应一个Segment，用于存放该表的所有数据。Table Space包含多个Segments，而每个Segment又包含多个Extents。

3. 关于Extents的描述，哪一项是正确的？
A. Extents可以跨多个data file存储
B. Extents由若干个Segments组成
C. 每个extent必须位于一个data file内
D. Extents是数据库中最小的存储单位
**答案：C**
**解析：** 每个extent必须位于一个data file内，不能跨文件。Extents由若干个Data Blocks组成，而不是Segments。

4. Data Block通常与什么一一对应？
A. Memory Page
B. Disk Block
C. Cache Line
D. Buffer Pool
**答案：B**
**解析：** Data Block一般与Disk Block一一对应，这是Oracle数据库中最小的I/O单位。

### 数据文件类型

8. Heap File的特点是什么？
A. 记录按某个字段有序存储
B. 使用哈希函数分配记录
C. 数据直接追加到文件末尾，无排序、无索引
D. 使用B+树索引组织数据
**答案：C**
**解析：** Heap File是最简单的文件组织方式，数据直接追加到文件末尾，没有排序也没有索引。

9. Heap File的插入操作时间复杂度是多少？
A. O(log n)
B. O(n)
C. O(1)
D. O(n log n)
**答案：C**
**解析：** Heap File的插入操作非常快，因为新记录直接插入到文件末尾，无需移动其他记录，时间复杂度为O(1)。

10. Heap File的等值查询平均需要读取多少页？
A. 所有页
B. 四分之一的页
C. 一半的页
D. 一个页
**答案：C**
**解析：** Heap File的等值查询需要扫描整个文件，平均读取一半的页才能找到目标记录。

11. Sorted files的查找时间复杂度是多少？
A. O(1)
B. O(log n)
C. O(n)
D. O(n log n)
**答案：B**
**解析：** Sorted files由于记录有序，可以使用二分查找，时间复杂度为O(log n)，远快于Heap File的O(n)。

12. Sorted files最适合哪种场景？
A. 频繁插入、少查询
B. 频繁查询、少更新
C. 频繁删除、少插入
D. 频繁更新、少查询
**答案：B**
**解析：** Sorted files适合频繁查询、少更新的场景，因为插入和删除效率低，需要保持顺序。

13. Hashed files使用什么方法将记录分配到不同的桶中？
A. 二分查找
B. B+树导航
C. 哈希函数
D. 线性搜索
**答案：C**
**解析：** Hashed files通过哈希函数将记录分配到不同的桶（bucket）中，实现快速的查找、插入和删除操作。

14. Hashed files的查找时间复杂度接近多少？
A. O(1)
B. O(log n)
C. O(n)
D. O(n²)
**答案：A**
**解析：** Hashed files的查找效率非常高，平均时间复杂度接近O(1)，因为只需计算哈希值并直接访问对应桶。

15. 当多个记录哈希到同一个桶时，会发生什么？
A. 自动创建新桶
B. 记录被拒绝插入
C. 冲突（collision）
D. 系统崩溃
**答案：C**
**解析：** 当多个记录哈希到同一个桶时，会发生冲突（collision），需要通过溢出页或链表等方式解决。

16. 解决Hashed files冲突的方法不包括以下哪项？
A. 使用溢出页（Overflow Page）
B. 链接溢出链表
C. 重新哈希整个文件
D. 使用线性探测
**答案：C**
**解析：** 重新哈希整个文件不是常见的冲突解决方法，通常使用溢出页、链表或线性探测等方法。

### B+树

19. B+树中，所有叶子节点位于什么位置？
A. 不同的层级
B. 同一最低层级
C. 根节点层级
D. 随机层级
**答案：B**
**解析：** B+树的一个重要特性是所有叶子节点都在同一最低层级，这保证了查询性能的一致性。

20. B+树叶子节点的指针指向什么？
A. 父节点
B. 兄弟节点
C. 记录
D. 索引键
**答案：C**
**解析：** B+树叶子节点的指针直接指向键对应的记录，而非父节点或其他节点。

21. 对于B+树非叶非根节点，如果最大键数量为n，则最小键数量是多少？
A. ⌊n/2⌋
B. ⌈(n+1)/2⌉-1
C. ⌈n/2⌉
D. ⌊(n+1)/2⌋
**答案：B**
**解析：** B+树非叶非根节点的最小键数量为⌈(n+1)/2⌉-1，这是B+树的平衡规则。

22. 对于B+树叶节点，如果最大键数量为n，则最小键数量是多少？
A. ⌊n/2⌋
B. ⌈(n+1)/2⌉-1
C. ⌈n/2⌉
D. ⌊(n+1)/2⌋
**答案：A**
**解析：** B+树叶节点的最小键数量为⌊n/2⌋，这是B+树的平衡规则。

23. B+树根节点的最小键数量是多少？
A. 0
B. 1
C. 2
D. n
**答案：B**
**解析：** B+树根节点的最小键数量为1，这是B+树的基本要求。

24. 当B+树节点键数量大于n时，会进行什么操作？
A. 合并
B. 删除
C. 分裂
D. 重组
**答案：C**
**解析：** 当B+树节点键数量大于n时，会进行分裂操作，将节点分成两个节点，并将中间键提升到父节点。

25. B+树插入时，分裂节点时，第n/2下标的键会被提到哪里？
A. 子节点
B. 兄弟节点
C. 父节点
D. 根节点
**答案：C**
**解析：** B+树插入时，分裂节点时，第n/2下标的键会被提到父节点中，作为分隔键。

26. B+树删除键值后，如果节点键数小于最小键数，首先尝试什么操作？
A. 合并节点
B. 借用兄弟节点的键
C. 删除父节点
D. 重建索引
**答案：B**
**解析：** B+树删除操作中，当节点键数不足时，首先尝试从兄弟节点借用键，以维持B+树的平衡。

27. B+树删除操作中，当叶子节点键数不足时，重新分配后父节点需要做什么？
A. 更新分隔键
B. 删除分隔键
C. 添加新键
D. 保持不变
**答案：A**
**解析：** B+树删除操作中，当叶子节点键数不足时，重新分配后父节点需要更新分隔键以反映新的键范围。

28. B+树中，非叶节点的指针数量与键数量的关系是什么？
A. 指针数量 = 键数量
B. 指针数量 = 键数量 + 1
C. 指针数量 = 键数量 - 1
D. 指针数量 = 2 × 键数量
**答案：B**
**解析：** B+树中，非叶节点的指针数量等于键数量加1，因为每个键分隔两个子树。

29. B+树中，叶子节点的指针数量与键数量的关系是什么？
A. 指针数量 = 键数量
B. 指针数量 = 键数量 + 1
C. 指针数量 = 键数量 - 1
D. 指针数量 = 2 × 键数量
**答案：A**
**解析：** B+树中，叶子节点的指针数量等于键数量，每个键对应一个指向记录的指针。

### 查询开销计算

38. Nested loop join的最佳情况开销是多少？
A. B_R + B_S
B. T_R * B_S + B_R
C. B_R * B_S + B_R
D. 2*(B_R+B_S) + (B_R+B_S)
**答案：A**
**解析：** Nested loop join的最佳情况是当外层关系R只有一条记录时，开销为B_R + B_S。

39. Nested loop join的最坏情况开销是多少？
A. B_R + B_S
B. T_R * B_S + B_R
C. B_R * B_S + B_R
D. 2*(B_R+B_S) + (B_R+B_S)
**答案：B**
**解析：** Nested loop join的最坏情况是当外层关系R的每条记录都要扫描整个内层关系S，开销为T_R * B_S + B_R。

40. Block nested loop join的最坏情况开销是多少？
A. B_R + B_S
B. T_R * B_S + B_R
C. B_R * B_S + B_R
D. 2*(B_R+B_S) + (B_R+B_S)
**答案：C**
**解析：** Block nested loop join的最坏情况是当内存只能容纳一个块时，开销为B_R * B_S + B_R。

41. Sort-Merge join的开销公式是什么？
A. B_R + B_S
B. cost of sorting + B_S + B_R
C. B_R * B_S + B_R
D. 2*(B_R+B_S) + (B_R+B_S)
**答案：B**
**解析：** Sort-Merge join的开销包括排序成本加上读取两个关系的成本。

42. Indexed nested loop join的开销公式是什么？
A. B_R + B_S
B. B_R + T_R * c
C. B_R * B_S + B_R
D. 2*(B_R+B_S) + (B_R+B_S)
**答案：B**
**解析：** Indexed nested loop join的开销是外层关系的块数加上外层关系记录数乘以内层关系的索引查找成本。

43. Hash join的开销公式是什么？
A. B_R + B_S
B. B_R + T_R * c
C. B_R * B_S + B_R
D. 2*(B_R+B_S) + (B_R+B_S)
**答案：D**
**解析：** Hash join的开销是构建哈希表和探测哈希表的成本，通常为2*(B_R+B_S) + (B_R+B_S)。

### 锁机制

66. S锁（Shared lock）用于什么操作？
A. 写操作
B. 读操作
C. 删除操作
D. 更新操作
**答案：B**
**解析：** S锁（共享锁）用于读操作，允许多个事务同时读取同一数据。

67. X锁（Exclusive lock）用于什么操作？
A. 读操作
B. 写操作
C. 查询操作
D. 排序操作
**答案：B**
**解析：** X锁（排他锁）用于写操作，确保只有一个事务可以修改数据。

68. IS锁（Intent Shared）表示什么？
A. 后续可能对子节点加S锁
B. 后续可能对子节点加X锁
C. 当前读，但打算后续写
D. 共享锁
**答案：A**
**解析：** IS锁（意图共享锁）表示事务打算在子节点上加S锁，用于层次化锁机制。

69. IX锁（Intent Exclusive）表示什么？
A. 后续可能对子节点加S锁
B. 后续可能对子节点加X锁
C. 当前读，但打算后续写
D. 排他锁
**答案：B**
**解析：** IX锁（意图排他锁）表示事务打算在子节点上加X锁，用于层次化锁机制。

70. SIX锁（Shared with Intent to eXclusive）表示什么？
A. 后续可能对子节点加S锁
B. 后续可能对子节点加X锁
C. 当前读，但打算后续写
D. 共享锁
**答案：C**
**解析：** SIX锁（共享锁+意图排他）表示当前读取数据，但打算后续进行写操作。

71. IS锁与哪种锁不相容？
A. S锁
B. X锁
C. IX锁
D. SIX锁
**答案：B**
**解析：** IS锁与X锁不相容，因为X锁会阻止其他事务读取数据。

72. IX锁与哪种锁不相容？
A. S锁
B. X锁
C. SIX锁
D. 以上都是
**答案：D**
**解析：** IX锁与S锁、X锁、SIX锁都不相容，因为它表示可能对子节点加X锁。

73. S锁与哪种锁不相容？
A. IX锁
B. SIX锁
C. X锁
D. 以上都是
**答案：D**
**解析：** S锁与IX锁、SIX锁、X锁都不相容，因为这些锁都可能影响读取操作的一致性。

74. SIX锁与除哪种锁外的所有锁都不相容？
A. S锁
B. X锁
C. IS锁
D. IX锁
**答案：C**
**解析：** SIX锁与IS锁相容，但与其他锁（S、X、IX）都不相容。

75. X锁与哪种锁不相容？
A. S锁
B. IS锁
C. IX锁
D. 所有锁
**答案：D**
**解析：** X锁与所有其他锁都不相容，因为它需要独占访问数据。
